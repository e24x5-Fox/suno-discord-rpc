Suno RPC
Broadcast API

Получай данные о текущем треке в реальном времени в любом приложении — на том же компьютере или по сети.

Что такое Broadcast API

Broadcast API — это WebSocket сервер встроенный в Suno RPC. Пока приложение запущено, любой клиент может подключиться к нему и получать обновления каждый раз когда меняется трек, пауза или позиция.

Адрес для подключения:
ws://localhost:6970
Порт можно изменить в настройках оверлея → Broadcast API

Сразу после подключения сервер пришлёт последний известный трек. Затем — каждое новое обновление в реальном времени.

Что такое «ВАШ IP» и зачем он нужен

Если подключаешься с того же компьютера — всегда используй localhost:

ws://localhost:6970

Если подключаешься с другого устройства в той же сети (телефон, ноутбук, второй ПК) — нужен локальный IP компьютера где запущен Suno RPC:

Windows
ipconfig
Открой CMD или PowerShell, введи команду. Ищи «IPv4-адрес» — обычно начинается с 192.168.x.x
Пример адреса
ws://192.168.1.5:6970
Замени 192.168.1.5 на реальный IP своего компьютера
⚠ Важно: IP-адрес должен быть в той же локальной сети. Через интернет без настройки роутера (проброс портов) подключиться не получится.

Формат сообщения

Каждое сообщение — JSON строка. Тип всегда track_update.

{
  "event":    "track_update",
  "title":    "Song Name",
  "artist":   "Artist Name",
  "url":      "https://suno.com/song/...",
  "coverUrl": "https://cdn.suno.com/image_...",
  "duration": 213,         // длина трека в секундах
  "elapsed":  42,          // позиция воспроизведения в секундах
  "isPaused": false,
  "timestamp": 1749308123  // Unix время отправки (сек)
}
ПолеТипОписание
eventstringВсегда "track_update"
titlestringНазвание трека
artiststringАвтор или "Suno AI" если неизвестен
urlstringСсылка на трек на Suno
coverUrlstringURL обложки (может быть пустым)
durationnumberДлина трека в секундах
elapsednumberТекущая позиция в секундах
isPausedbooleantrue — пауза, false — играет
timestampnumberUnix-время отправки события

Аудио-данные (FFT визуализация)

Помимо track_update, сервер рассылает второй тип событий — audio_data. Это сырые данные FFT-анализа звука из браузера, обновляются каждые 50 мс (~20 раз в секунду).

Требования для получения аудио-данных:
· Расширение Chrome должно захватить вкладку Suno (происходит автоматически при воспроизведении)
· Трек должен активно играть — на паузе данные не поступают

Формат события audio_data

{
  "event":  "audio_data",
  "fft":    [0, 12, 87, 143, 201, 178, ...],  // 64 числа, каждое 0–255
  "volume": 94                               // среднее по всем бинам, 0–255
}
ПолеТипОписание
eventstringВсегда "audio_data"
fftnumber[]Массив из 64 чисел (0–255). Каждый элемент — амплитуда частотного бина. Индекс 0 — самые низкие частоты (бас), индекс 63 — высокие (высокочастотные детали)
volumenumberСреднее значение по всем 64 бинам. Удобно как общий уровень громкости (0–255)

Как фильтровать события

Оба события приходят в один WebSocket на порту 6970. Различать их нужно по полю event:

ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);

  if (msg.event === "track_update") {
    // метаданные трека
    console.log(msg.title, msg.artist);
  }

  if (msg.event === "audio_data") {
    // FFT: 64 значения 0–255
    drawEqualizer(msg.fft);
    // общая громкость: 0–255
    updateVolumeMeter(msg.volume);
  }
};javascript

Примеры кода

Python — базовое подключение

# pip install websockets
import asyncio, websockets, json

async def main():
    async with websockets.connect("ws://localhost:6970") as ws:
        print("Подключён. Ожидаем треки...")
        async for msg in ws:
            data = json.loads(msg)
            status = "⏸" if data["isPaused"] else "▶"
            print(f"{status} {data['title']} — {data['artist']}")

asyncio.run(main())python

Python — с автоматическим переподключением

import asyncio, websockets, json

async def on_track(data: dict):
    # Сюда твоя логика
    print(f"Трек: {data['title']} | elapsed: {data['elapsed']}s")

async def listen():
    url = "ws://localhost:6970"
    while True:
        try:
            async with websockets.connect(url) as ws:
                print("✅ Подключён")
                async for msg in ws:
                    await on_track(json.loads(msg))
        except Exception as e:
            print(f"⚠ Отключён: {e}. Reconnect через 3 сек...")
            await asyncio.sleep(3)

asyncio.run(listen())python

Использование в OBS

Можно сделать Now Playing оверлей прямо в OBS через Browser Source:

  1. Создай HTML файл с нужным дизайном
    Пример кода ниже — вставь его в файл nowplaying.html и открой в браузере для проверки
  2. В OBS: Добавить → Browser Source
    Тип источника — «Браузер». Не «URL», а локальный файл
  3. Укажи путь к файлу
    Нажми «Обзор» и выбери свой nowplaying.html
  4. Убедись что Suno RPC запущен
    Browser Source подключится автоматически как только найдёт сервер на localhost:6970

Частые вопросы

Почему данные не приходят?

Убедись что:
· Suno RPC запущен и в настройках включён Broadcast API
· Расширение браузера подключено (в оверлее зелёная точка «Расширение»)
· На Suno.com открыт трек и он играет (данные приходят только при активном воспроизведении)
· Порт 6970 не занят другим приложением

Можно ли подключить несколько клиентов одновременно?

Да. Broadcast API рассылает одни и те же данные всем подключённым клиентам. Количество отображается в оверлее Suno RPC.

Как узнать свой IP?

Windows: Открой CMD → введи ipconfig → найди «IPv4-адрес» (обычно 192.168.x.x)

Или: Нажми Win+I → Сеть и Интернет → Свойства своей сети → прокрути вниз

Приложение на другом ПК не видит сервер

Возможные причины:
· Брандмауэр Windows блокирует входящие соединения на порт 6970. Добавь правило: netsh advfirewall firewall add rule name="SunoRPC" protocol=TCP dir=in localport=6970 action=allow
· Устройства в разных сетях — оба должны быть в одной Wi-Fi/LAN сети
