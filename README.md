# 🎵 Suno → Discord Rich Presence

Десктопное приложение для Windows: живёт в трее, показывает текущий трек из
Suno AI в активности Discord.

**[⬇ Скачать установщик](https://github.com/e24x5-Fox/suno-discord-rpc/releases/latest)**
— `Suno RPC Setup *.exe` в последнем релизе.

Что попадает в Discord:
- **Название трека** и **исполнитель**
- **Прогресс-бар** (заполняющаяся полоса)
- **Обложка трека**

А когда музыка не играет — показывает видео, которое ты смотришь на YouTube:
название, канал, таймкод, превью и кнопку на само видео. Музыка всегда в
приоритете, переключение автоматическое.

---

## Как это работает

```
suno.com  →  Расширение Chrome  →  Python-бэкенд  →  Discord
(плеер)      (читает данные)       (WebSocket)       (Rich Presence)
                                        ↑
                                  Electron-окно
                                (интерфейс и трей)
```

Приложение состоит из двух процессов: **Electron** держит окно, трей и меню, а
**Python** — всю логику (WebSocket-серверы, Discord RPC, статистику). Electron
запускает Python сам и общается с ним по локальному HTTP на порту 6972.

## Установка — 3 шага

### Шаг 1 — Создай Discord приложение (1 раз)

1. Иди на [discord.com/developers/applications](https://discord.com/developers/applications)
2. Нажми **New Application**
3. Дай любое имя, например `Suno Player`
4. Скопируй **Application ID** — он понадобится дальше

> 💡 Опционально: во вкладке **Rich Presence → Art Assets** можно загрузить
> логотип — он будет показываться как маленькая иконка рядом с обложкой.

---

### Шаг 2 — Запусти приложение

**Из готовой сборки:** скачай `Suno RPC Setup *.exe` со страницы
[Releases](https://github.com/e24x5-Fox/suno-discord-rpc/releases/latest),
установи и запусти — иконка появится в системном трее. Client ID вводится в
окне приложения, на вкладке **Настройки**, перезапуск не нужен.

> Установщик не подписан сертификатом, поэтому SmartScreen на первом запуске
> покажет «Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом
> случае». Подпись стоит денег и для проекта на двух пользователей не окупается.

**Из исходников** (нужны Python 3.11+ и Node.js 18+):
```bash
pip install -r python/requirements.txt
cd desktop && npm install && npm start
```

Electron сам запустит Python-бэкенд, поэтому отдельно `suno_rpc.py`
запускать не надо. При старте окно свёрнуто в трей — открой его двойным
кликом по иконке. Для разработки удобнее `npm run dev`: окно показывается
сразу и открывается DevTools.

Если бэкенд не поднялся, окно покажет это явно, с последними строками его
вывода — вкладка **Логи** там же.

### Шаг 3 — Установи расширение браузера

Расширения живут в отдельных репозиториях — там же их установка, сборка и issues:

| Репозиторий | Зачем | Браузеры |
|---|---|---|
| **[suno-rpc-extension](https://github.com/e24x5-Fox/suno-rpc-extension)** | **Обязательное.** Читает плеер suno.com | Chromium |
| **[youtube-rpc-extension](https://github.com/e24x5-Fox/youtube-rpc-extension)** | По желанию: активность YouTube, когда Suno молчит | Chromium, Firefox |
| **[audio-fx-extension](https://github.com/e24x5-Fox/audio-fx-extension)** | Не связано с RPC: эквалайзер, ревёрб, дилей, 8D для suno.com | Chromium, Firefox |

Коротко для основного: `chrome://extensions` → «Режим разработчика» →
«Загрузить распакованное расширение» → папка склонированного репозитория.

> ⚠️ **Важно:** расширение работает только пока запущено приложение.
> Запускай `Suno RPC` **перед** тем как открываешь Suno.

Suno-расширение в Firefox не работает, и дело не в упаковке: оно опирается на
`offscreen` и `tabCapture` (оба только в Chromium), а `ws://` Firefox из
контекста расширения не выпускает вовсе. YouTube-расширение поэтому и сделано
на обычном HTTP — оно в Firefox работает штатно.

После установки видео с YouTube будет показываться в Discord, когда в Suno
ничего не играет.

Что настраивается на вкладке **▶ YouTube** в окне приложения: включение,
тип активности (Смотрит / Играет / Слушает), **название в шапке активности**
и обе кнопки под активностью — первая по умолчанию ведёт на само видео,
вторая свободная.

> 💡 Первая строка в Discord — это глагол типа активности плюс название. По
> умолчанию Discord берёт туда имя твоего Discord-приложения, из-за чего под
> роликом с YouTube писалось «Смотрит Suno AI». Поле «Название в шапке
> активности» это переопределяет; для Suno оно тоже есть — на вкладке
> «Настройки», пустое значение оставляет имя приложения.

Приоритет источников:

| Suno | YouTube | Что в Discord |
|---|---|---|
| играет | играет | Suno |
| пауза | играет | YouTube |
| закрыт | играет | YouTube |
| играет | пауза | Suno |
| пауза | пауза | тот, что играл последним |

Статистика просмотров ведётся отдельно от музыкальной и не смешивается с ней:
отчёт открывается в том же окне кнопкой в его шапке.

## Использование

1. Запусти `Suno RPC` — иконка появится в трее
2. Открой [suno.com](https://suno.com) в Chrome
3. Начни воспроизведение любого трека
4. Через несколько секунд в Discord появится статус

Иконка в трее показывает состояние **цветом точки** в углу: зелёная — Discord
подключён и трек играет, жёлтая — подключён, но пауза, серая — Discord
недоступен. Сам рисунок иконки выбирается в настройках и на состояние не
влияет. Двойной клик открывает окно, правая кнопка — меню.

**Нажми на иконку расширения** чтобы проверить:
- 🟢 `Подключён` — приложение работает
- `▶ Играет` — трек найден и транслируется

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Не удалось подключиться к Discord` | Убедись что Discord запущен, потом «Переподключить» в меню трея. Проверь Client ID |
| Окно пишет «Бэкенд не отвечает» | Скорее всего остался старый процесс на портах 6969–6972 — сними его в диспетчере задач |
| Статус не появляется | Включи **Настройки → Конфиденциальность → Отображать активность** в Discord |
| Расширение не видит трек | Обнови страницу suno.com после установки расширения |
| Прогресс-бар не отображается | Это нормально на паузе — Discord показывает полосу только при воспроизведении |
| Обложка не отображается | Discord иногда кеширует изображения. Подожди 1-2 минуты |

## Структура файлов

```
suno-discord-rpc/
├── desktop/              ← Electron-приложение (окно, трей, меню)
│   ├── package.json
│   └── src/
│       ├── main.js       ← трей, окна, запуск бэкенда
│       ├── preload.js    ← мост между окном и бэкендом
│       ├── index.html    ← интерфейс
│       └── icons/
├── python/
│   ├── suno_rpc.py       ← бэкенд: WebSocket серверы + Discord RPC + control API
│   ├── suno_stats.py     ← статистика прослушиваний, HTML-отчёт
│   ├── youtube_stats.py  ← статистика просмотров, отдельно от музыкальной
│   ├── requirements.txt
│   └── suno_rpc.spec     ← сборка бэкенда (PyInstaller)
├── build.bat             ← полная сборка установщика
└── build-icons.py        ← генерирует наборы иконок из исходных PNG
```

Расширения — в отдельных репозиториях
([suno-rpc-extension](https://github.com/e24x5-Fox/suno-rpc-extension),
[youtube-rpc-extension](https://github.com/e24x5-Fox/youtube-rpc-extension),
[audio-fx-extension](https://github.com/e24x5-Fox/audio-fx-extension)), у
каждого свой `build.py` для упаковки в `.zip`/`.xpi`.

> Расширение для YouTube ходит к бэкенду по HTTP, а не по WebSocket, как
> Suno-расширение. Firefox не выпускает `ws://` из контекста расширения:
> `moz-extension://` считается защищённым, и небезопасный WebSocket оттуда либо
> блокируется молча, либо повышается до `wss://`. Подробности — в
> [AI_GUIDE.md](AI_GUIDE.md).

**Порты:**

| Порт | Что | Доступен |
|---|---|---|
| 6969 | WebSocket для расширения Chrome | localhost |
| 6970 | Broadcast API для визуализаторов | вся локальная сеть |
| 6971 | Приём истории прослушиваний с телефона | вся локальная сеть |
| 6972 | Control API — окно управляет бэкендом | только localhost |

## Когда ничего не играет

Вкладка **💤 Ожидание** — что показывать в Discord, если молчат и Suno, и
YouTube. Настраиваются все поля активности: название в шапке, обе строки,
картинка, подписи, таймер простоя и две кнопки.

В текст можно подставлять значения: `{tracks}` — треков за месяц, `{hours}` —
время прослушивания за месяц, `{last_track}` и `{last_artist}` — что играло
последним.

Отсчёт идёт от **паузы**, а не от закрытия вкладки: расширение продолжает слать
данные, пока вкладка открыта. Задержка настраивается там же — по умолчанию
30 секунд, 0 переключает сразу по паузе.

Если шаблон выключить, активность просто снимается. Без него и без снятия в
Discord навсегда висел бы последний трек, доигравший полчаса назад.

> 💡 Картинку Discord скачивает сам, поэтому файл с диска сюда не подходит —
> нужна прямая ссылка на изображение либо ключ ассета из Developer Portal →
> твоё приложение → Rich Presence → Art Assets.

## Окно и автозапуск

Вкладка **Настройки** → «Окно и запуск». Всё применяется сразу по клику,
кнопка «Сохранить» на этой вкладке к ним не относится — она для настроек
бэкенда.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Запускать вместе с Windows | выкл | Приложение стартует при входе в систему — всегда свёрнутым в трей |
| Стартовать свёрнутым в трей | вкл | Окно не показывается при обычном запуске |
| ✕ сворачивает в трей | вкл | Крестик прячет окно, а не завершает приложение |
| Сворачивать в трей | выкл | «Свернуть» убирает окно в трей, а не на панель задач |
| Поверх всех окон | выкл | |
| Открывать одним кликом по трею | выкл | Двойной клик работает всегда |
| Запоминать размер и положение | вкл | Окно открывается там же, где было закрыто |

Настройки хранятся не в конфиге бэкенда, а рядом с выбором иконки — в
`ui-settings.json` в `%APPDATA%\suno-rpc-desktop`. Так окно знает, показываться
ли ему, ещё до того, как бэкенд успел подняться.

Если монитор, на котором стояло окно, отключили — восстановится только размер,
позицию выберет система: иначе окно открылось бы за пределами экрана.

Полоса заголовка и рамка окна — свои, фиолетовые, под цвет иконки. Системная
полоса скрыта, а кнопки свернуть/развернуть/закрыть остаются настоящими (Snap
Layouts работают), просто перекрашены. Цвет намеренно не настраивается.

## Иконка приложения

В окне приложения, вкладка **Настройки** → «Иконка приложения» — четыре
варианта на выбор. Применяется сразу: трей, кнопка на панели задач, окно.

Иконка самого файла программы в проводнике и у закреплённого ярлыка при этом
не меняется — она зашита в `.exe` при сборке. Чтобы сменить и её, поставь
нужную картинку первой в списке `VARIANTS` в `build-icons.py`, выполни
`python build-icons.py` и пересобери приложение.

Свои картинки добавляются так: положить квадратный PNG (лучше 1000×1000, с
прозрачностью) в `desktop/src/icons/source/`, дописать строку в `VARIANTS`
в `build-icons.py` и запустить `python build-icons.py`.

## Сборка установщика (Windows)

```bash
build.bat
```

Скрипт делает всё сам: собирает Python-бэкенд через PyInstaller, ставит
зависимости Electron и упаковывает установщик в `desktop\dist\`. Требуются
Python и Node.js — остальное ставится автоматически.

Если бэкенд не менялся, пересобирать его незачем — достаточно Electron-части:

```bash
cd desktop && npm run dist
```

Версия установщика берётся из `version` в `desktop/package.json` — её и стоит
поднимать перед выпуском релиза, чтобы имя файла совпадало с тегом.

Если что-то пошло не так (Discord не подключается, ошибка статистики и т.п.) —
открой вкладку **⚠ Логи** в окне приложения: там последние события и ошибки, их
можно скопировать одной кнопкой, например чтобы приложить к issue.

## Технические детали

- Расширение читает `<audio>` элемент страницы каждые 2 секунды
- Данные передаются через WebSocket на `localhost:6969`
- Окно и бэкенд — разные процессы; Electron запускает бэкенд и завершает его
  при выходе, а бэкенд сам закрывается, если Electron упал
- Discord обновляется не чаще 1 раза в 15 секунд (ограничение API)
- Прогресс-бар реализован через `start_timestamp` + `end_timestamp`
- Обложка передаётся как прямая ссылка на CDN Suno
